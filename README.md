# 하루기록 — 일일 업무일지

회사 업무일지 양식에 맞춰 하루의 업무를 작성하고, Supabase 계정별로 저장하거나 PDF로 내려받는 정적 웹 앱입니다.

## 실행

- 내 컴퓨터에서: `index.html`을 웹 브라우저로 엽니다.
- GitHub Pages: <https://poreQw.github.io/task/>

`main` 브랜치에 변경 사항을 올리면 `.github/workflows/pages.yml`이 사이트를 배포합니다. 저장소의 **Settings → Pages → Build and deployment → Source**가 **GitHub Actions**로 설정되어 있어야 합니다. 첫 배포가 완료된 뒤 위 주소에서 앱을 열 수 있습니다.

### 파일 구성

- `index.html`: 앱 화면 구조와 메뉴·폼·모달 마크업
- `styles.css`: 반응형 화면, 색상, 인쇄 및 PDF 표시 스타일
- `app.js`: 저장·인증·검색·메모 분류·보고서/PDF 동작
- `supabase/`: 공개 클라이언트 설정과 계정별 RLS 데이터베이스 스키마

GitHub Pages 배포 workflow는 위 세 앱 파일과 `supabase/config.js`를 함께 게시합니다.

## Supabase 및 계정별 클라우드 저장 설정

1. Supabase에서 프로젝트를 만들고 **Project URL**과 공개용 **publishable key**(또는 legacy `anon` key)를 확인합니다. `service_role` key는 브라우저에 넣지 마세요.
2. Supabase **SQL Editor**에서 [`supabase/schema.sql`](./supabase/schema.sql) 내용을 실행합니다. 테이블과 RLS 정책은 각 사용자가 자신의 기록만 조회·추가·수정·삭제하도록 제한합니다.
3. [`supabase/config.js`](./supabase/config.js)에서 `url`과 `anonKey`를 프로젝트 값으로 바꿉니다. 이 파일의 anon/publishable key는 공개 클라이언트 키이며, 접근 제어는 RLS 정책이 담당합니다.
4. Supabase 대시보드의 **Authentication → URL Configuration**에서 **Site URL**을 `https://poreqw.github.io/task/`로 설정하고 **Redirect URLs**에도 `https://poreqw.github.io/task/`를 추가하세요. 허용 목록에 추가하는 것만으로는 충분하지 않습니다. **Site URL**이 `http://localhost:3000`으로 남아 있으면, 명시적인 리디렉션 주소가 없는 이메일은 로컬 주소로 이동합니다. **Authentication → Email Templates → Confirm signup**은 기본 `{{ .ConfirmationURL }}` 링크를 사용해야 합니다. 사용자 지정 링크를 만들었다면 `localhost:3000`을 고정하지 말고 Supabase의 `{{ .RedirectTo }}` 및 `{{ .TokenHash }}`를 사용해야 합니다. 별도의 `/auth/callback` 페이지는 필요하지 않습니다. 앱은 Supabase 세션 토큰이 포함된 표준 콜백과 `token_hash` 콜백을 처리합니다. `otp_expired`는 링크가 만료되었거나 이미 사용되었다는 뜻이므로 새 확인 메일을 요청한 뒤 가장 최근 메일의 링크를 한 번만 여세요. 기존 링크는 복구할 수 없습니다. **Confirm email**이 켜져 있으면 새 계정은 이메일 확인이 필요하며, 이 설정을 꺼도 기존 미인증 계정이 자동으로 인증되지는 않습니다. 이메일 확인 없이 가입하려면 **Authentication → Sign In / Providers → Email → Confirm email**을 끄세요. 이메일 확인을 유지한다면 **Authentication → Users**에서 기존 계정 상태를 확인하세요. 계정 삭제 시 연결된 업무일지도 함께 삭제될 수 있으므로 함부로 삭제하지 마세요.
5. 설정 파일과 변경 사항을 `main` 브랜치에 올리면 GitHub Actions가 GitHub Pages에 배포합니다. 별도의 GitHub 토큰은 필요하지 않습니다. Pages의 소스는 **GitHub Actions**여야 합니다.

앱 상단의 저장 위치 표시를 확인하세요.

- **로컬 저장 · 이 브라우저**: 로그아웃 상태에서 기록은 작성한 브라우저에만 저장됩니다. 다른 브라우저나 기기에서는 자동으로 보이지 않습니다.
- **클라우드 저장 · Supabase**: 로그인 상태에서 기록은 로그인 계정에 저장됩니다. 다른 기기에서도 같은 계정으로 로그인하면 조회할 수 있습니다. 계정 간 데이터는 Supabase RLS 정책으로 분리합니다.
- **템플릿**은 로그인 여부와 관계없이 현재 브라우저에 저장되며 클라우드 동기화 대상이 아닙니다.

### 로컬 기록을 클라우드로 옮기기

1. 기록이 있는 기기에서 로그아웃 상태인지 상단 저장 위치를 확인합니다.
2. **업무일지 목록 → 전체 백업**으로 JSON 파일을 내보냅니다. 백업에는 현재 브라우저의 기록과 템플릿이 포함됩니다.
3. 같은 기기에서 클라우드 계정으로 로그인합니다. 상단에 **클라우드 저장 · Supabase**가 표시되는지 확인합니다.
4. **업무일지 목록 → 백업 복원**에서 방금 만든 JSON 파일을 선택하고 확인합니다. 같은 날짜에 이미 있는 클라우드 기록은 백업 내용으로 바뀝니다.
5. 목록에서 기록을 확인한 다음 다른 기기에서 **같은 계정**으로 로그인하고 목록을 새로고침해 다시 확인합니다. 클라우드 기록을 확인하기 전까지 원본 기기의 로컬 데이터나 백업 파일을 지우지 마세요.

Supabase 설정을 비워 두어도 앱은 로컬 저장 모드로 동작합니다.

## 기능

- 이름, 날짜와 ① 지시받은 업무, ② 완료한 업무, ③ 해결하지 못한 문제, ④ 오늘 배운 내용, ⑤ 내일 할 일을 기록합니다.
- 업무 진행 상태를 완료/진행 중으로 관리하고 대시보드에서 전체·완료·진행 중 통계와 최근 업무일지를 확인합니다.
- 자유 메모를 키워드 규칙으로 업무 항목별 분류하고, 입력 문장을 업무일지 표현으로 다듬습니다. 메모 분류는 AI 기능이 아니며, 분류 결과를 저장 전에 확인해야 합니다.
- 로그인 없이 업무일지를 작성하고 로컬에 저장할 수 있으며, 계정을 만들고 로그인하면 사용자별 클라우드 저장 및 기기 간 동기화를 사용할 수 있습니다.
- 어두운 파란색 사이드 내비게이션에서 대시보드, 기록 목록, 작성, PDF 보고서와 사용 가이드로 이동하며, 각 메뉴는 서로 분리된 화면으로 표시됩니다.
- 작성자·업무 내용·날짜 범위·진행 상태로 기록을 찾고, 월간 달력과 전체/완료/진행 중/연속/최근 7일 통계를 확인할 수 있습니다.
- 작성 중인 내용을 미리 보고, 저장된 보고서를 수정하거나 업무일지 목록에서 삭제할 수 있습니다.
- 내일 할 일을 줄별 체크리스트로 관리하고, 자주 쓰는 업무 내용을 템플릿으로 저장해 적용할 수 있습니다.
- 모든 기록과 템플릿을 JSON 백업 파일로 내보내고, 백업 파일을 병합 복원할 수 있습니다.
- 완성한 업무일지를 복사하거나 텍스트 파일로 저장하고, 기기의 공유 메뉴로 전달할 수 있습니다.
- 브라우저의 글꼴로 한국어·중국어가 보이도록 A4 PDF를 생성해 인쇄 창 없이 다운로드합니다.
- 반응형 화면과 A4 인쇄용 업무일지 서식을 제공합니다.

## 저장 및 공유 안내

- 상단 **로컬 저장 · 이 브라우저 / 클라우드 저장 · Supabase** 표시로 현재 위치를 확인하세요. 로컬 저장은 다른 기기에 동기화되지 않습니다. 클라우드 기록은 같은 계정으로 로그인한 기기에서 볼 수 있습니다. 로컬 기록 이동은 위의 백업·복원 절차를 따르세요.
- 브라우저 데이터 삭제에 대비해 **전체 백업**으로 JSON 파일을 보관하세요. **백업 복원**은 기존 날짜의 기록을 백업 내용으로 바꾸고 나머지 기록은 유지합니다.
- 업무일지를 다른 사람에게 보내려면 공유 메뉴를 사용하거나 텍스트를 복사해 메신저/메일에 붙여 넣으세요. 로컬 데이터 자체는 공유되지 않습니다.
- PDF를 만들려면 결과 화면에서 **PDF 다운로드**를 누르거나 **저장 후 PDF 다운로드**를 누르세요. PDF는 기본 다운로드 폴더로 내려받으며, 브라우저의 다운로드 위치 설정에 따라 저장 위치를 물어볼 수 있습니다.
- PDF는 한국어/중국어가 보이도록 페이지를 이미지로 렌더링해 만듭니다. 따라서 PDF 안의 글자는 선택하거나 검색할 수 없습니다.
- 메모 분류와 문장 다듬기는 입력 문장을 기준으로 처리되므로 저장 전에 결과를 확인하세요.

### 핵심 흐름 회귀 테스트

분리된 앱 파일을 로컬 브라우저에서 확인했습니다. 작성·로컬 저장, 목록·상세 조회, 수정 저장, 새로고침 후 재조회, 삭제가 모두 통과했고 JavaScript 실행 오류는 없었습니다. PDF 샘플도 각각 1페이지와 8페이지로 생성되어 PDF 구조를 확인했습니다.

두 번째 실제 기기에서의 동기화와 제3자 무설명 사용성 테스트는 이 환경에서 참여 기기·사용자를 제공받지 못해 수행하지 않았습니다. 클라우드 동기화 완료 판정은 위 로컬 백업 이전 절차를 실제 기기 A와 B에서 수행한 뒤 내려야 합니다.
